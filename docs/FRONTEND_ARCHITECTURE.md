# Frontend architecture

Этот документ фиксирует обязательные правила развития интерфейса Tyuttori. Цель — чтобы новый разработчик быстро понимал, где искать код и как добавлять функции без появления новых визуальных вариантов одного и того же элемента.

## Стек

- Next.js и React — маршруты, серверные и клиентские компоненты.
- Tailwind CSS 4 — компоновка и стили.
- shadcn/ui на базе Radix UI / Base UI — низкоуровневые элементы интерфейса.
- CSS variables в `app/globals.css` — цвета, радиусы, размеры контролов и базовые интервалы.
- `class-variance-authority` — именованные варианты компонентов.
- `lucide-react` — единый набор иконок.

Ant Design и Bootstrap не используются.

## Слои компонентов

```text
app/                         маршруты и сборка страниц
components/ui/               базовые примитивы: Button, Input, Dialog, Typography
components/common/           переиспользуемые составные блоки продукта
components/features/<name>/  компоненты конкретной функции
lib/                         общая предметная логика и клиенты API
app/api/                     HTTP-обработчики; без JSX и визуальной логики
db/                          схемы базы
```

`components/ui` не должен знать об учениках, уроках или оплатах. `components/common` может описывать повторяемый визуальный шаблон, но не бизнес-сценарий. Всё, что относится только к сообщениям, расписанию или материалам, помещается в соответствующую feature-папку.

Существующие крупные файлы переносятся в эту структуру постепенно при работе над затрагиваемой функцией. Массовое переписывание ради перемещения файлов не выполняется.

## Дизайн-система

Источники истины:

- цвета и темы — семантические переменные `--background`, `--card`, `--primary`, `--destructive`;
- радиусы и размеры — `--radius-card`, `--radius-control`, `--control-height`;
- карточки — `AppCard` из `components/common/app-card.tsx`;
- кнопки — `Button` и его `variant`/`size`;
- заголовки и текст — `Typography` либо заголовки `AppCard`;
- раскрытие длинных списков — `ShowMoreButton`.

Нельзя задавать новый цвет, высоту кнопки, радиус, тень или типографический размер прямо внутри feature-компонента, если в дизайн-системе уже существует подходящий вариант. Если варианта действительно не хватает, сначала он добавляется в базовый компонент с понятным именем, затем используется в функции.

Tailwind-интервалы используют стандартную шкалу с шагом 4 px. Допустимые основные уровни: `gap-2` (8 px), `gap-3` (12 px), `gap-4` (16 px), `gap-5` (20 px), `gap-6` (24 px). Произвольные значения применяются только для расчётной геометрии, а не для обычных отступов.

## Правило переиспользования

Перед созданием JSX разработчик проверяет `components/ui`, затем `components/common`, затем папку текущей функции. Если одинаковая конструкция появилась второй раз, она выносится в отдельный компонент в рамках той же задачи.

Feature-компонент отвечает за данные и сценарий, базовый компонент — за внешний вид и состояния. Нельзя копировать длинные наборы классов между экранами.

## Размер файлов и границы функций

- Страница или контейнер компонует функции, но не содержит реализацию всех диалогов и карточек.
- Компонент ориентировочно свыше 250 строк рассматривается как кандидат на разделение.
- API-файл ориентировочно свыше 300 строк разделяется на схемы, запросы и обработчики по предметным областям.
- Типы функции располагаются рядом с функцией; действительно общие типы — в `lib` или `features/<name>/types.ts`.
- Клиентские запросы одной функции собираются в `features/<name>/api.ts`, а не дублируются в компонентах.

## Локализация и доступность

Любой новый видимый текст одновременно получает русский и английский варианты. Проверяются также ошибки API, placeholder, `aria-label`, пустые и загрузочные состояния. Интерактивные элементы должны использовать `Button`, `Input`, `Select`, `Dialog` и другие доступные примитивы, а не стилизованные `div`.

## Проверка нового интерфейса

Перед завершением функции проверяются:

1. мобильная и десктопная ширина;
2. светлая и тёмная темы;
3. русский и английский языки;
4. длинный текст и пустое состояние;
5. клавиатурный фокус и отсутствие горизонтального переполнения;
6. сборка, типы и релевантные тесты.
