# Перенос Tutor Platform на VPS и PostgreSQL

## Статус и границы

Работа ведётся в ветке `migration/vps-postgres`. Текущий сайт на Cloudflare Workers, D1 и Supabase Auth остаётся production и источником истины до отдельного подтверждения владельца на переключение. Команды публикации, изменение DNS, покупка VPS и финальный экспорт данных не входят в локальную подготовку.

## Целевая схема

- Caddy завершает HTTPS и проксирует запросы в приложение.
- Next.js работает в standalone-режиме на Node.js 22 в непривилегированном контейнере.
- PostgreSQL 17 хранит предметные данные, авторизацию, сессии, лимиты и журнал фоновых заданий.
- Отдельный Node-процесс обслуживает периодические задания и использует advisory lock.
- SMTP-провайдер отправляет приглашения и восстановление пароля.
- Зашифрованные резервные копии PostgreSQL выгружаются во внешнее S3-совместимое хранилище.

## Этапы

1. Подготовить воспроизводимую локальную сборку, контейнеры, health checks и конфигурацию без секретов. Выполнено локально.
2. Создать PostgreSQL-схему, повторяемый импорт D1 и автоматическую сверку. Выполнено локально.
3. Заменить D1-доступ транзакционным PostgreSQL-слоем, сохранив проверки ролей и арендатора. Выполнено локально.
4. Подключить Argon2id и непрозрачные серверные сессии с ротацией и отзывом. Выполнено локально.
5. Перенести одноразовые приглашения, установку и восстановление пароля, SMTP, общие лимиты запросов и фоновые задания. Выполнено локально.
6. Подготовить резервное копирование, восстановление и эксплуатационные проверки VPS. Выполнено локально.
7. Прогнать тесты и сценарии преподавателя, ученика и администратора на staging-копии.
8. В согласованное окно включить режим только для чтения, снять новый экспорт, импортировать и сверить данные.
9. Переключить домен, наблюдать метрики и ошибки; старый контур не удалять до окончания периода отката.

## Обязательные проверки импорта

- Совпадают количества строк каждой таблицы, кроме новых PostgreSQL-служебных таблиц.
- Сохранены исходные текстовые ID, `group_id`, ссылки на серии, события, баланс, запросы, приглашения и уведомления.
- Нет нарушений внешних ключей и осиротевших ссылок.
- Баланс каждого ученика равен исходной сумме `lesson_units`.
- Для урока не появляется более одного `lesson_charge`; возврат одной оплаты не дублируется.
- Активные уроки одного кабинета не пересекаются; ожидающие запросы соблюдают частичные уникальные ограничения.
- Все эпохи D1 преобразованы в UTC без сдвига, а календарные даты серий не меняются.

## Локальные команды PostgreSQL

- `npm run db:generate:postgres` — генерирует добавочную миграцию из `db/postgres/schema.ts`.
- `DATABASE_URL=... npm run db:migrate:postgres` — применяет миграции под advisory lock.
- `DATABASE_URL=... npm run db:import:d1 -- /absolute/path/export.sqlite` — импортирует полный SQLite-экспорт D1 в пустую PostgreSQL-базу.

Импорт выполняется одной транзакцией и отказывается работать с непустыми предметными таблицами. Он сохраняет исходные ID, переводит миллисекундные эпохи в `timestamptz`, восстанавливает sequence `data_changes`, сверяет количество строк, внешние ссылки и баланс каждого ученика. Любое нарушение, включая пересечение активных уроков, откатывает весь импорт.

## Совместимость рабочего API

Стандартная Node-сборка подменяет только модуль доступа к D1 на `db/postgres-d1.ts`. Проверки ролей, `workspace_id`, схем входных данных и бизнес-операции остаются общими для обоих контуров. Адаптер выполняет запросы PostgreSQL параметризованно, переводит временные значения между эпохой приложения и `timestamptz`, а `batch` выполняет одной транзакцией. Cloudflare-сборка продолжает импортировать настоящий D1 binding и не включает Node/PostgreSQL-драйвер.

Smoke-тест этапа API должен включать как минимум полную загрузку кабинета, автоматическое завершение прошлых уроков, создание ученика, создание урока, оплату, замену доступности и изменение карточки ученика. Тест проводится только на временной импортированной копии.

## Авторизация Node-контура

В Node-сборке пароли хешируются Argon2id. В PostgreSQL сохраняется только хеш пароля и SHA-256-хеш случайного 256-битного токена сессии; сам токен передаётся только в `HttpOnly`, `SameSite=Lax`, а в production также `Secure` cookie. Обновление сессии атомарно отзывает прежний токен, выход отзывает текущий. Без `DATABASE_URL` и `AUTH_SECRET` длиной не менее 32 символов авторизация закрывается с `503`.

Успешные и неуспешные попытки входа записываются в `auth_audit_events`; email и IP там сохраняются только как HMAC-хеши. Блокировка кабинета немедленно лишает его участников доступа, но отдельный платформенный администратор сохраняет возможность открыть админку и снять блокировку. Перенесённый из Supabase пользователь без локального пароля получает его через одноразовую ссылку установки или восстановления.

Одноразовые ссылки приглашений действуют 14 дней, ссылка восстановления пароля — один час. В PostgreSQL сохраняются только SHA-256-хеши токенов; использованные и заменённые токены повторно не принимаются. SMTP настраивается только переменными окружения. Ответ восстановления одинаков для существующего и неизвестного email.

Общие лимиты запросов хранятся атомарно в `rate_limit_buckets`: публичная авторизация и запросы ученика ограничены 10 обращениями в минуту, остальные изменения API — 60 обращениями в минуту. Ключи HMAC-хешируются и не раскрывают cookie или IP.

Отдельный сервис `worker` в Compose каждые 15 минут запускает завершение уроков и очистку просроченных служебных записей. PostgreSQL advisory lock не допускает одновременную обработку несколькими экземплярами, а результат каждого запуска записывается в `job_runs`.

## Условия переключения

- Есть проверенная резервная копия D1 и проверенное восстановление PostgreSQL.
- Production-сборка, миграции и smoke-тесты проходят на чистом окружении.
- Владелец проверил вход администратора, приглашение преподавателя, вход преподавателя и ученика, расписание, баланс и блокировку кабинета.
- Подтверждены домен, SMTP, VPS, S3-хранилище и окно работ.
- Выполнен restore drill из зашифрованного внешнего backup по регламенту [`VPS_OPERATIONS.md`](VPS_OPERATIONS.md).

## Откат

До открытия записи можно вернуть старый Cloudflare-контур. После первой записи в PostgreSQL откат выполняется развёртыванием предыдущего проверенного Node-образа поверх той же PostgreSQL-базы. Возврат на старую D1 без обратной миграции запрещён.
