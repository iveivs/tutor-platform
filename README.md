# Tutor Platform

Веб-приложение для частных преподавателей и их учеников. Первый пользователь продукта — преподаватель барабанов, но архитектура рассчитана на дальнейшее подключение других репетиторов и переход к подписной SaaS-модели.

Проект находится в активной разработке. Основной контур публикуется на VPS Selectel по адресу [tyuttori.ru](https://tyuttori.ru) и использует PostgreSQL и собственную Argon2id-авторизацию. Прежний Cloudflare-контур сохранён только для контролируемого отката и архивной совместимости; порядок проверок описан в [`docs/VPS_MIGRATION.md`](docs/VPS_MIGRATION.md).

## Что уже работает

### Кабинет преподавателя

- обзор занятий на выбранный день;
- календарь в режимах дня, недели и месяца;
- список учеников с поиском и фильтрами;
- постоянное и плавающее расписание;
- автоматическое создание конкретных уроков из постоянного расписания на 90 дней вперёд;
- карточка ученика;
- баланс оплаченных занятий, включая отрицательные значения;
- добавление ученика, урока и оплаты;
- бесплатные пробные занятия для новых посетителей без засорения списка учеников;
- архивирование, восстановление и подтверждаемое окончательное удаление учеников;
- запросы на перенос, отмену и создание нового занятия;
- подтверждение и отклонение запросов;
- светлая и тёмная тема с сохранением выбора;
- рабочие настройки профиля с изменением имени преподавателя;
- добровольное подключение Telegram для напоминаний и запросов учеников;
- закрытое приглашение новых преподавателей платформенным администратором;
- блокировка и подтверждаемое удаление кабинетов преподавателей;
- адаптивный интерфейс для компьютера и телефона.

### Кабинет ученика

- персональный вход по приглашению;
- автоматическое продление безопасной сессии без повторного входа каждый час;
- ближайший урок, баланс и история оплат;
- запрос переноса или отмены ближайшего урока;
- предложение даты и времени нового урока при плавающем расписании;
- уведомления о решении преподавателя и отрицательном балансе;
- добровольное подключение Telegram для напоминаний и изменений расписания.

## Основные правила продукта

- Оплата может быть разовой или абонементом на несколько занятий.
- Баланс хранится в занятиях и может становиться отрицательным.
- После окончания проведённого урока должно автоматически списываться одно занятие.
- Если ученик не пришёл, урок всё равно считается проведённым.
- Ученик не изменяет расписание напрямую: он отправляет запрос преподавателю.
- Запрос отмены можно отправить не позднее 23:59 дня, предшествующего уроку.
- Если отмена запрошена вовремя, но преподаватель ещё не ответил, занятие не должно списываться.
- При переносе ученик может предложить новое время, окончательное решение принимает преподаватель.
- Для плавающего расписания ученик может предложить новый урок, но преподаватель должен его подтвердить.
- Двойной урок создаётся как два связанных последовательных занятия: переносится и отменяется целиком, а после проведения списывает два занятия.
- В интерфейсе ученика показывается количество занятий на балансе и отдельная история оплат.

## Локальный запуск

### Требования

- Node.js 22.13 или новее;
- npm;
- Git.

### 1. Установка

```bash
npm ci
```

### 2. Настройка окружения

```bash
cp .env.example .env.local
```

В `.env.local` нужно указать локальный `DATABASE_URL`, `AUTH_SECRET` длиной не менее 32 символов и остальные используемые интеграции. Примерные значения нельзя переносить в production.

### 3. Применение миграций PostgreSQL

```bash
DATABASE_URL='postgresql://tutor:local-password@127.0.0.1:5432/tutor_platform' npm run db:migrate:postgres
```

Скрипт получает адрес базы из окружения и применяет только ещё не выполненные миграции под advisory lock.

### 4. Запуск приложения

```bash
npm run dev
```

После запуска приложение доступно по адресу [http://localhost:3000](http://localhost:3000).

Локальные команды разработки явно включают демонстрационный режим только для loopback-адресов. Рабочая Node-версия закрывается с ошибкой `503`, если не настроены PostgreSQL или серверный секрет авторизации, а не предоставляет демонстрационный доступ.

## Работа с миграциями

1. Изменить `db/postgres/schema.ts`.
2. Выполнить `npm run db:generate:postgres`.
3. Проверить созданный SQL-файл.
4. Применить только новую миграцию к локальной базе.
5. Не изменять миграции, которые уже применялись на сервере.

Старые команды `db:generate`, D1-схема и демонстрационные данные относятся только к совместимому Cloudflare-контуру.

## Безопасность

- Пароли хранятся в PostgreSQL только в виде стойких Argon2id-хешей и никогда не журналируются или не передаются клиенту.
- Токен восстановления приходит во фрагменте ссылки, немедленно удаляется из адресной строки и передаётся только собственному API для установки нового пароля.
- Токены приглашений должны сохраняться только в виде криптографического хеша.
- Доступ к данным должен проверяться на сервере по пользователю и кабинету.
- Каждый API-запрос ограничен кабинетом вошедшего пользователя; данные разных преподавателей не смешиваются.
- Роль администратора платформы не расширяет `/api/app-data`: администратор видит только метаданные кабинета и журнал административных действий.
- Заблокированный кабинет закрывается для всех его memberships при каждой серверной проверке сессии; данные при этом не удаляются.
- Короткоживущий токен доступа и токен продления хранятся только в защищённых `HttpOnly` cookie.
- Клиентские идентификаторы нельзя использовать как доказательство прав доступа.
- Локальные файлы окружения, база, сборка и зависимости исключены из Git.

## Настройка авторизации

Рабочий сайт использует собственную авторизацию на VPS: пользователи, Argon2id-хеши паролей, одноразовые токены и серверные сессии находятся в PostgreSQL. Supabase в рабочем контуре не используется. Для запуска на VPS настраиваются `DATABASE_URL`, `AUTH_SECRET`, `PUBLIC_APP_URL`, `PLATFORM_ADMIN_EMAIL` и SMTP-переменные по образцу `.env.example`.

Рабочая почта отправляется через Selectel с `smtp.mail.selcloud.ru:1127` по TLS от имени `no-reply@tyuttori.ru`. Домен должен иметь подтверждённые SPF, DKIM и DMARC. SMTP-пароль хранится только в серверном `.env`.

Файлы и переменные Supabase остаются в репозитории только для прежнего Cloudflare-контура на период технического отката. Они не участвуют во входе на `tyuttori.ru` и не должны использоваться для новых учётных записей.

После настройки вход станет обязательным. В карточке нового ученика нажмите «Пригласить ученика»: приложение покажет персональную ссылку, которую можно отправить через системное меню или скопировать вручную. Ученик открывает её, задаёт личный пароль и получает доступ только к своему кабинету.

Открытая регистрация преподавателей отключена. Новый кабинет создаётся только по персональной ссылке, которую платформенный администратор выпускает для конкретных имени и email. Преподаватель открывает ссылку, задаёт пароль и получает независимый `workspace`. Ссылка одноразовая, действует 14 дней, а в PostgreSQL хранится только её SHA-256-хеш.

При принятии приглашения пользователь отдельными галочками подтверждает Пользовательское соглашение, Правила размещения контента и согласие на обработку персональных данных. Для несовершеннолетнего приглашение принимает законный представитель с дополнительным подтверждением. Сервер сохраняет тип и редакцию документа, время, роль участника, источник и сведения браузера в `legal_acceptances`. Публичные документы доступны в разделе [`/legal`](https://tyuttori.ru/legal), а на странице каждого документа доступна PDF-версия.

Заполненные юридические оригиналы хранятся локально в `private/legal-documents/`, исключены из Git и из контекста сборки Docker. На VPS эта папка монтируется в контейнер только для чтения. Для рабочего запуска в ней должны находиться пять Markdown-файлов и соответствующие PDF; редактируемые DOCX можно хранить рядом как локальный архив.

Админка доступна из настроек владельца-администратора или отдельному аккаунту из `PLATFORM_ADMIN_EMAIL`. Она показывает владельца, дату создания, последнюю активность, статус и число учеников, позволяет приглашать преподавателей, блокировать/разблокировать кабинет и сохраняет изменения доступа в журнале. Приглашённым сейчас выдаётся бессрочный бесплатный доступ; поля модели отдельно сохраняют способ и срок доступа для будущих пробных периодов и платных тарифов. Окончательное удаление возможно только после блокировки и повторного ввода email преподавателя. Пароли, уроки, оплаты и содержимое кабинета через административный API не выдаются.

На экране входа доступно восстановление пароля по email. Сервер создаёт одноразовый токен сроком на один час, хранит в PostgreSQL только его SHA-256-хеш и отправляет ссылку через настроенный SMTP. После установки нового Argon2id-пароля ссылка погашается, а остальные активные сессии пользователя отзываются. Ответ формы не сообщает, зарегистрирован ли введённый адрес.

## Telegram-уведомления

Telegram подключается каждым преподавателем или учеником добровольно из своего кабинета. Приложение создаёт одноразовую ссылку на бота сроком на 15 минут; после команды `/start` приватный `chat_id` связывается с текущим `member`. Токен привязки хранится только как SHA-256-хеш. Отключение Telegram деактивирует связь и отменяет ожидающие отправки.

Бот отправляет только три категории сообщений:

- одно персональное напоминание за 24 часа до урока ученику и одно сводное расписание дня преподавателю;
- изменение расписания ученика преподавателем;
- новый запрос ученика на отмену, перенос или занятие преподавателю.

Предметное изменение и внутренняя запись `notifications` остаются источником истины. Триггер PostgreSQL атомарно добавляет подходящее событие в `telegram_deliveries`, а `scripts/run-maintenance.mjs` каждые 15 минут ставит напоминания, доставляет очередь и повторяет временно неудачные отправки до пяти раз. Уникальный `dedupe_key` исключает повторное сообщение. При ответе Telegram `403` подключение автоматически отключается.

VPS Selectel не может напрямую подключиться к `api.telegram.org`, поэтому рабочая схема использует отдельный минимальный Cloudflare Worker из `workers/telegram-relay/`. Telegram отправляет webhook шлюзу, шлюз передаёт его в `https://tyuttori.ru/api/telegram/webhook`, а сервер отправляет сообщения через защищённый путь шлюза. На Cloudflare хранятся токен бота, webhook-secret и отдельный relay-secret; на VPS нужны `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_API_BASE_URL` и `TELEGRAM_RELAY_SECRET`. Прямой режим через `TELEGRAM_BOT_TOKEN` сохранён для окружений, где Telegram доступен без шлюза. Без полной конфигурации интерфейс показывает, что бот ещё настраивается, а остальные функции приложения продолжают работать.

## Прежнее размещение в Cloudflare

Конфигурация прежнего контура хранится в `wrangler.deploy.jsonc`. Рабочий сайт больше не публикуется этой командой: production работает на VPS Selectel с PostgreSQL.

```bash
npm run build
npx wrangler d1 migrations apply tutor-platform-db --remote --config wrangler.deploy.jsonc
npx wrangler deploy --config wrangler.deploy.jsonc --secrets-file .env.local
```

Эти команды сохранены только для контролируемого отката и локальной совместимости. Новые рабочие данные после переключения домена записываются только в PostgreSQL.

Cloudflare запускает фоновую обработку каждые 15 минут. Она списывает завершённые уроки даже тогда, когда преподаватель и ученики не открывают приложение. Своевременный необработанный запрос отмены по-прежнему блокирует списание.

Раздел «История» объединяет события уроков, операции баланса и запросы учеников. Преподаватель может фильтровать ленту по ученику и типу события, а ученик видит только собственную историю. Переносы сохраняют прежнее и новое время.

Открытый кабинет автоматически синхронизируется без перезагрузки страницы. В активной вкладке лёгкая проверка выполняется каждые 30 секунд, в скрытой — каждые 5 минут; при возвращении на вкладку или восстановлении интернета проверка выполняется сразу. Сервер сначала читает адресный журнал изменений и загружает только изменившиеся разделы — например, запросы и уведомления, не затрагивая оплаты и всю историю.

## Текущие ограничения

- автоматическое списание может произойти в течение 15 минут после окончания урока;
- Telegram-бот `@tyuttori_bot` и production webhook активированы через защищённый relay; привязка кабинета преподавателя и двусторонняя доставка подтверждения проверены в production. Перед полноценным релизом остаётся пройти привязку ученика и проверить все разрешённые события расписания;
- групповые занятия оставлены для будущего расширения.

## Статус проекта

Основной MVP работает на VPS Selectel с PostgreSQL, собственной авторизацией, Caddy и Docker Compose. Рабочий домен — `tyuttori.ru`. Регистрация преподавателей закрыта и доступна только по приглашению администратора; ученики подключаются по приглашению преподавателя.

Основные юридические документы имеют редакцию 1.0, а Правила размещения пользовательского контента обновлены до редакции 1.2 от 11 октября 2026 года. Обязательные согласия разделены, не отмечены заранее и журналируются в базе. Актуальная редакция отдельно регулирует заметки, фотографии и библиотеку учебных документов преподавателя.

Почтовый домен подтверждён в Selectel, SPF/DKIM/DMARC настроены. Telegram-модуль активирован в production: бот `@tyuttori_bot`, webhook через Cloudflare relay и серверная очередь работают; привязка преподавателя и ответ бота проверены. Следующим шагом остаётся ручная проверка ученика и каждого разрешённого уведомления.

10 октября 2026 года архивная D1 была транзакционно объединена с уже работающей PostgreSQL после отдельного production `pg_dump`, локальной репетиции и production dry-run. Сохранены как прежние, так и новые записи: в рабочей базе 15 учеников, 6 ученических email, 11 серий расписания, 183 урока и 37 операций баланса. Совпавшие владелец и ученик связаны по нормализованному email, Argon2id-пароли и новые сессии не перезаписывались. Исторические уведомления импортированы без повторной постановки в Telegram.

Последние завершённые изменения:

- добавлены личные текстовые сообщения между учеником и преподавателем с историей, прочитанностью и защитой от спама;
- кабинет ученика получил широкую двухколоночную компоновку для десктопа, фото профиля и выбор цвета аватара;
- преподаватель видит выбранное учеником оформление и при желании задаёт собственный цвет карточки только для своего интерфейса;
- к уроку можно вести общую заметку ученика, общую и личную заметки преподавателя; автор редактирует и удаляет свои записи;
- домашнее задание отделено от заметок: преподаватель задаёт работу, ученик ведёт собственный ответ или комментарий, а существующие документы и фотографии остаются в материалах урока;
- каждый участник может приложить до пяти фотографий по 5 МБ, сервер оптимизирует их в WebP, а worker удаляет изображения через 90 дней после урока;
- преподаватель может один раз загрузить PDF, DOC или DOCX до 25 МБ в закрытую библиотеку и прикрепить его к нескольким урокам; ученик видит только документы своих уроков;
- библиотека ограничена 50 загрузками за календарный месяц и 5 ГБ активных документов на кабинет, одинаковые файлы не дублируются, документы хранятся до явного удаления;
- библиотека поддерживает папки и теги, поиск, фильтры PDF/Word, сортировку по недавнему использованию и показывает уроки с учениками, которым назначен каждый материал;
- файл можно заменить новой версией без изменения ссылок на уроки; прежний S3-объект удаляется worker после атомарного переключения;
- отдельное принятие правил контента защищает создание заметок и загрузку файлов, а лимиты запросов, часовые и месячные квоты и общий объём кабинета ограничивают злоупотребления;
- имя и фамилия ученика разделены, email остаётся необязательным;
- данные ученика можно исправить из его карточки;
- постоянное расписание можно задать сразу при создании ученика;
- у выбора времени появились кнопки изменения на час;
- перенос изменяет исходный урок, удаление действительно убирает его из расписания;
- генерация постоянного расписания защищена от активных дубликатов;
- тёмная тема стала нейтрально-графитовой, поле календаря отделено от фона, выходные выделены сильнее.
