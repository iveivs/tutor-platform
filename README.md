# Tutor Platform

Веб-приложение для частных преподавателей и их учеников. Первый пользователь продукта — преподаватель барабанов, но архитектура рассчитана на дальнейшее подключение других репетиторов и переход к подписной SaaS-модели.

Сейчас проект работает локально и находится в активной разработке. Интерфейс уже связан с постоянной локальной базой данных: изменения не исчезают после обновления страницы.

## Что уже работает

### Кабинет преподавателя

- обзор занятий на выбранный день;
- календарь на месяц;
- список учеников с поиском и фильтрами;
- постоянное и плавающее расписание;
- карточка ученика;
- баланс оплаченных занятий, включая отрицательные значения;
- добавление ученика, урока и оплаты;
- запросы на перенос, отмену и создание нового занятия;
- подтверждение и отклонение запросов;
- светлая и тёмная тема с сохранением выбора;
- адаптивный интерфейс для компьютера и телефона.

### Кабинет ученика

Сейчас представлен интерфейс будущего кабинета: ближайший урок, баланс, история оплат и действия для запроса переноса или отмены. Полная авторизация и привязка ученика через персональную ссылку будут реализованы на следующем этапе.

## Основные правила продукта

- Оплата может быть разовой или абонементом на несколько занятий.
- Баланс хранится в занятиях и может становиться отрицательным.
- После окончания проведённого урока должно автоматически списываться одно занятие.
- Если ученик не пришёл, урок всё равно считается проведённым.
- Ученик не изменяет расписание напрямую: он отправляет запрос преподавателю.
- Запрос отмены можно отправить не позднее 23:59 дня, предшествующего уроку.
- Если отмена запрошена вовремя, но преподаватель ещё не ответил, занятие не должно списываться.
- При переносе ученик может предложить новое время, окончательное решение принимает преподаватель.
- Для плавающего расписания ученик может предложить новый урок, но преподаватель должен его подтвердить.
- Двойной урок создаётся как два обычных последовательных занятия.
- В интерфейсе ученика показывается количество занятий на балансе и отдельная история оплат.

- TypeScript

- Tailwind CSS 4

## Архитектура

```text
app/
  api/app-data/       API чтения и изменения рабочих данных
  globals.css         общая светлая и тёмная тема
  layout.tsx          корневая разметка приложения
  page.tsx            главная страница
components/
  tutor-app.tsx       основные экраны и пользовательские сценарии
  theme-*.tsx         управление темой
  ui/                 базовые компоненты интерфейса
db/
  schema.ts           схема базы данных
  d1.ts               безопасный доступ к D1
  seed.local.sql      локальные демонстрационные данные
drizzle/
  *.sql               последовательные миграции базы
public/
  favicon.svg         иконка приложения
```

Клиентский интерфейс обращается к `/api/app-data`. API выполняет проверку входных данных и работает с базой через подготовленные запросы. Все рабочие записи принадлежат отдельному `workspace`, поэтому данные разных преподавателей можно изолировать без изменения основной модели.

## Структура данных

В базе используются девять основных таблиц:

| Таблица | Назначение |
| --- | --- |
| `workspaces` | независимые кабинеты преподавателей или будущих школ |
| `users` | учётные записи системы авторизации без хранения паролей |
| `members` | преподаватели и ученики внутри кабинета |
| `lesson_series` | шаблоны постоянного еженедельного расписания |
| `lessons` | конкретные занятия с датой и временем |
| `balance_entries` | оплаты, списания, возвраты и корректировки баланса |
| `lesson_requests` | запросы на отмену, перенос или новый урок |
| `invitations` | безопасные одноразовые приглашения учеников |
| `notifications` | будущие уведомления пользователей |

Баланс не хранится одним изменяемым числом. Он вычисляется как сумма операций: оплата добавляет занятия, проведённый урок списывает одно. Такая модель сохраняет понятную историю и позволяет исправлять ошибки отдельными корректировками.

Подробнее правила модели описаны в [`db/README.md`](db/README.md).

## Локальный запуск

### Требования

- Node.js 22.13 или новее;
- npm;
- Git.

### 1. Установка

```bash
npm ci
```

### 2. Сборка конфигурации

```bash
npm run build
```

### 3. Применение миграции к локальной базе

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB \
  --local \
  --config dist/server/wrangler.json \
  --persist-to .wrangler/state \
  --file drizzle/0000_silent_hellcat.sql
```

Миграцию нужно применять один раз к новой локальной базе.

### 4. Добавление демонстрационных данных

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB \
  --local \
  --config dist/server/wrangler.json \
  --persist-to .wrangler/state \
  --file db/seed.local.sql
```

Скрипт безопасно запускать повторно: существующие демонстрационные записи не дублируются.

### 5. Запуск приложения

```bash
npm run dev
```

После запуска приложение доступно по адресу [http://localhost:5173](http://localhost:5173).

## Работа с миграциями

1. Изменить `db/schema.ts`.
2. Выполнить `npm run db:generate`.
3. Проверить созданный SQL-файл.
4. Применить только новую миграцию к локальной базе.
5. Не изменять миграции, которые уже применялись на сервере.

Демонстрационные данные не входят в миграции и хранятся отдельно в `db/seed.local.sql`.

## Безопасность

- Пароли не хранятся в базе приложения.
- Токены приглашений должны сохраняться только в виде криптографического хеша.
- Доступ к данным должен проверяться на сервере по пользователю и кабинету.
- Клиентские идентификаторы нельзя использовать как доказательство прав доступа.
- Локальные файлы окружения, база, сборка и зависимости исключены из Git.

## Настройка авторизации

Авторизация использует Supabase Auth на бесплатном тарифе, а рабочие данные остаются в D1. Это разделяет вход пользователей и предметные данные приложения, не привязывая расписание к одному поставщику авторизации.

1. Создайте бесплатный проект в Supabase.
2. В разделе API скопируйте URL проекта и анонимный ключ.
3. В разделе API скопируйте `service_role` key. Не публикуйте его и не добавляйте в GitHub.
4. Скопируйте `.env.example` в `.env.local` и заполните три значения.
5. Перезапустите локальное приложение.
6. Создайте в Supabase первого преподавателя с email `teacher@example.com` или замените этот email в локальных данных на свой.

После настройки вход станет обязательным. При создании нового ученика ссылка-приглашение автоматически копируется в буфер обмена. Ученик открывает её, задаёт личный пароль и получает доступ только к своему кабинету.
